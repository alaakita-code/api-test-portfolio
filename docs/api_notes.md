# API 探索筆記

- 測試對象：JSONPlaceholder
- Base URL：`https://jsonplaceholder.typicode.com`
- 最後更新：2026-11-14
- 詳細的原始紀錄在 `docs/api_observed.md`；本檔是整理後的摘要。

## 一、基本資訊（來源：官方首頁）

| 項目 | 內容 |
|---|---|
| 驗證機制 | 無；不需金鑰或註冊 |
| 資源與筆數 | posts 100、comments 500、albums 100、photos 5000、todos 200、users 10 |
| 支援的方法 | GET、POST、PUT、PATCH、DELETE |
| 巢狀路徑 | 只支援一層，例如 `/users/1/posts` |
| 篩選 | 只能用查詢參數，例如 `?userId=1` |
| 寫入是否保存 | 不保存；POST、PUT、PATCH、DELETE 只回傳模擬結果 |

## 二、探索問題與答案

寫測試之前列出的 10 個問題，以及實際觀察到的答案。

| 編號 | 問題 | 答案 | 依據 |
|---|---|---|---|
| Q1 | `GET /posts/1` 回傳哪些欄位、型別為何 | userId、id 為整數；title、body 為字串 | 觀察 3 #2 |
| Q2 | `POST /posts` 的狀態碼與回傳的 id | 201；id 為 101 | 觀察 3 #5 |
| Q3 | `DELETE /posts/1` 的狀態碼與回應內容 | 200；`{}` | 觀察 3 #8 |
| Q4 | `/posts/0`、`/posts/101`、`/posts/-1`、`/posts/abc` 的狀態碼 | 全部 404，內容 `{}` | 觀察 3 #10–13 |
| Q5 | 不存在的路徑回什麼狀態碼 | 404，內容 `{}` | 觀察 3 #14 |
| Q6 | `?userId=999` 回空清單還是錯誤 | 200 與空清單 `[]` | 觀察 3 #15 |
| Q7 | `POST /posts` 送空內容是否被拒絕 | 不會被拒絕；回 201 與 `{"id":101}` | 觀察 3 #16 |
| Q8 | `PUT /posts/101`、`DELETE /posts/101` 的狀態碼 | PUT 回 404；DELETE 回 200 | 觀察 3 #17、#18 |
| Q9 | 同一請求重複送，結果是否一致 | 一致 | 觀察 3 #19、#20 |
| Q10 | 一般回應時間 | 本機實測平均每個測試約 1 秒（含測試工具啟動時間，僅兩次執行） | 本機執行：10 個測試 10.73 秒、21 個測試 20.69 秒 |

Q1 到 Q9 的答案先由瀏覽器觀察取得，之後已用 Python requests 在本機執行測試驗證，結果相同。

## 三、已知限制

- 寫入不保存，所以無法驗證「新增後再查詢得到同一筆」這類資料一致性。
- API 不驗證輸入（Q7），也沒有登入機制，所以無法展示輸入驗證與權限測試。
- 對不存在的 id，更新與刪除的行為不一致（Q8）。
- 讀取類的回應多來自 Cloudflare 快取，重複請求測試驗證到的可能是快取的一致性。
- 這是假資料服務，測試結果只代表測試設計與自動化能力，不代表真實產品的品質。
- 測試依賴外部服務；服務中斷時測試會失敗，這屬於環境問題，不是腳本問題。
